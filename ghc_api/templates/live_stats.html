How to read this

tok/s is decode speed: output tokens divided by generation time, where generation time is the total request duration minus the time to first token. A slow queue upstream therefore shows up as a large TTFT, not as a low tok/s. The headline tok/s column is token-weighted across the whole window (total tokens / total generating seconds); the median and percentile columns describe individual requests, so a single long reply cannot dominate them.
Non-streaming responses have no measurable TTFT; for them the full duration counts as generation time, and they are excluded from the TTFT columns (streaming share is visible in the JSON as streaming_requests). Requests with no output tokens or under 0.05s of generation are excluded from speed metrics but still counted as requests and errors.
All numbers come from an in-memory ring of recent finished requests and cover this process run only; they reset on restart. For historical analysis across days use Request Stats.
